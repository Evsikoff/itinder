# ITinder

ITinder — платформа, где IT-соискатели подтверждают свой грейд, а рекрутёры собирают команды под проекты. Всё происходит в 3D: вы регистрируетесь на станции метро, садитесь в поезд, попадаете в комнату и работаете за компьютером в ней.

> [!TIP]
> **Запускайте ITinder со звуком: включите колонки или наушники.** Звук — часть интерфейса. На станции гудит метро, при переходах между страницами слышны шаги, у табличек, доски и клетки с шариками свои звуки. Распределительная шляпа озвучивает свой вердикт, в комнате щёлкают клавиатура и мышь компьютера, презентации окон на рабочем столе идут с голосом диктора.
>
> Браузеры разрешают звук только после действия пользователя. На станции звук включается кнопкой «Старт» на стартовой странице, в комнате — первым щелчком или нажатием клавиши. В комнате звук можно выключить кнопкой динамика в левом верхнем углу.

## Из чего состоит ITinder

ITinder — это три приложения, которые раздаёт один локальный сервер на Python:

| Приложение | Папка с исходниками | Адрес | Что нужно для запуска |
| --- | --- | --- | --- |
| **Станция метро** — стартовая страница, регистрация, вход, распознавание резюме, выбор роли | `app/web` | `/app/web/` (с `/` перенаправляет сюда) | ничего: обычные модули браузера, сборка не нужна |
| **3D-комната** с компьютером | `resume3` | `/resume3/` | собрать в `resume3/public` |
| **Рабочий стол** «операционной системы» на мониторе в комнате | `portfolio-inner-site` | `/os/` | собрать в `portfolio-inner-site/build` |
| **Сервер и API** | `app/tools/serve.py` | `/api/…` | Python и пакеты из `app/tools/requirements.txt` |

Приложения вложены друг в друга:

```
Одна вкладка браузера: http://127.0.0.1:8770
│
├─ /app/web/   Станция метро (app/web)
│                 «Старт» → регистрация или вход → выбор роли → посадка в поезд
│                        │  переход по ссылке
│                        ▼
├─ /resume3/   3D-комната (resume3)
│                 └─ монитор в комнате = <iframe src="/os/">
│                        ▼
├─ /os/        Рабочий стол (portfolio-inner-site) — работает ВНУТРИ комнаты
│
└─ /api/…      API на Python — его вызывают все три приложения
```

Комната не содержит рабочего стола: она загружает его в `<iframe>` с адреса `/os/` того же сервера. Поэтому все три приложения должны открываться с одного сервера `app/tools/serve.py`:

- кто вошёл, станция запоминает в `sessionStorage` вкладки, и рабочий стол внутри iframe читает эту запись, только если у него тот же адрес;
- рабочий стол обращается к `/api/…` по относительному адресу, без отдельного сервера и настроек CORS.

Сервер раздаёт готовые сборки, а не исходники. Без сборки `resume3` адрес `/resume3/` не откроется, без сборки `portfolio-inner-site` монитор в комнате останется пустым.

## Локальный запуск по шагам

Ниже команды для **Windows (PowerShell)** и для **macOS / Linux (bash, zsh)**. Все команды, кроме тех, где сказано иначе, выполняются из корня репозитория.

### Шаг 1. Скачайте репозиторий

```sh
git clone https://github.com/Evsikoff/itinder.git
cd itinder
```

### Шаг 2. Установите пакеты Python

Удобнее ставить их в виртуальное окружение `.venv`: так пакеты не попадут в системный Python. Папка `.venv` исключена из Git.

Windows (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r app/tools/requirements.txt
```

Если PowerShell не даёт запустить `Activate.ps1`, разрешите скрипты для текущего окна командой `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` и повторите активацию.

macOS / Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r app/tools/requirements.txt
```

Окружение действует только в этом окне терминала. В новом окне перед запуском сервера активируйте его снова, вторая строка команд выше.

### Шаг 3. Соберите рабочий стол (`portfolio-inner-site`)

```sh
cd portfolio-inner-site
npm ci --no-audit --no-fund
npm run build
cd ..
```

Сборка появится в `portfolio-inner-site/build`. Её адрес `/os/` задан полем `homepage` в `portfolio-inner-site/package.json`, менять его не нужно.

### Шаг 4. Соберите 3D-комнату (`resume3`)

```sh
cd resume3
npm ci --no-audit --no-fund
npm run build
cd ..
```

Сборка появится в `resume3/public`. Это самый тяжёлый шаг: нужно около 4 ГБ памяти и несколько минут.

`npm ci` на шагах 3 и 4 нужен только в первый раз и после изменений в `package-lock.json`. После правок исходников достаточно `npm run build`.

### Шаг 5 (необязательно). Подключите свои ключи нейросетей

Без ключей ITinder работает, кроме двух функций, которым нужна нейросеть:

- распознавание резюме распределительной шляпой: специализацию и грейд можно выбрать вручную;
- проверка текстовых ответов и кода в «Задачах на грейд».

Ключей в репозитории нет: каждый, кто запускает ITinder, подключает свои, и запросы к нейросетям оплачиваются с его аккаунтов. ITinder спрашивает две нейросети: сначала Gemini, а если она не ответила, ответила с ошибкой или думает слишком долго — DeepSeek. Хватит ключа одной из них, с двумя надёжнее.

#### 1. Получите ключ

| Нейросеть | Где получить ключ | Переменная |
| --- | --- | --- |
| Gemini (Google) | [Google AI Studio → API keys](https://aistudio.google.com/app/apikey), кнопка «Create API key». Если сайт не открывается в вашей стране, понадобится VPN | `GEMINI_API_KEY` |
| DeepSeek | [DeepSeek Platform → API keys](https://platform.deepseek.com/api_keys), кнопка «Create new API key». Ключ показывают один раз — скопируйте его сразу. Запросы оплачиваются с баланса аккаунта: пополните его в разделе Top up | `DEEPSEEK_API_KEY` |

#### 2. Запишите ключ в файл `.env.local`

Создайте в корне репозитория, рядом с `README.md`, текстовый файл с именем `.env.local` и такими строками:

```dotenv
GEMINI_API_KEY=ваш-ключ-gemini
DEEPSEEK_API_KEY=ваш-ключ-deepseek
```

- одна переменная на строку, **без пробелов вокруг `=`**: строку `GEMINI_API_KEY = …` сервер не найдёт;
- кавычки вокруг ключа не нужны, но и не мешают;
- если ключ только один, вторую строку удалите.

Файл можно создать из терминала, подставив свои ключи.

Windows (PowerShell):

```powershell
Set-Content -Path .env.local -Value "GEMINI_API_KEY=ваш-ключ-gemini", "DEEPSEEK_API_KEY=ваш-ключ-deepseek"
```

macOS / Linux:

```sh
printf 'GEMINI_API_KEY=%s\nDEEPSEEK_API_KEY=%s\n' 'ваш-ключ-gemini' 'ваш-ключ-deepseek' > .env.local
```

Если создаёте файл в Блокноте Windows, при сохранении выберите «Тип файла: Все файлы», иначе получится `.env.local.txt`.

`.env.local` исключён из Git (правило `.env*` в `.gitignore`) и из Docker build context, а сервер его наружу не отдаёт. Не переименовывайте файл и не вписывайте ключи в код или в `.env.example`: оттуда они попадут в публичный репозиторий.

Вместо файла ключи можно задать переменными окружения с теми же именами — в том окне терминала, где потом запускается сервер: в PowerShell `$env:GEMINI_API_KEY = "ваш-ключ-gemini"`, в bash и zsh `export GEMINI_API_KEY=ваш-ключ-gemini`. Если ключ задан и так, и в `.env.local`, действует переменная окружения.

#### 3. Проверьте ключи

Не запуская ITinder, задайте нейросетям пробный вопрос (из корня репозитория, с активированным `.venv`):

```sh
python app/tools/llm.py "Ответь JSON-списком из трёх названий баз данных"
```

Если ключ работает, команда покажет, какая нейросеть ответила, и сам ответ:

```json
{
  "llm": "Gemini",
  "model": "gemini-3.8-flash",
  "data": ["PostgreSQL", "MySQL", "MongoDB"]
}
```

Ответила DeepSeek, а над ответом строка «Не справилась Gemini …» — значит, не работает ключ Gemini, причина в той же строке. Если не справились обе, команда напишет «Ошибка: Ни одна нейросеть не дала годный ответ» и причину для каждой:

| Причина | Что сделать |
| --- | --- |
| `не задана переменная окружения GEMINI_API_KEY` (или `DEEPSEEK_API_KEY`) | файла `.env.local` нет в корне репозитория, он сохранился как `.env.local.txt` или в строке с ключом есть пробелы вокруг `=` |
| `ключ API не подошёл` | ключ скопирован не полностью или отозван — создайте новый |
| `на счёте не хватает денег` | пополните баланс DeepSeek |
| `слишком много запросов или кончилась квота` | подождите или проверьте лимиты ключа в кабинете нейросети |
| `доступ запрещён: ключ, страна или защита Cloudflare` | сервис недоступен из вашей страны — включите VPN |
| `… не ответил за … с` | сервис не отвечает — проверьте интернет и VPN |

#### 4. Запустите сервер

Сервер перечитывает `.env.local` при каждом запросе к нейросети, поэтому после правки файла перезапускать его не нужно. Переменные окружения он видит только те, что были заданы до его запуска: после `$env:…` или `export` перезапустите `serve.py` в том же окне. В Docker ключи из того же файла передаёт `--env-file .env.local` (см. [Запуск в Docker](#запуск-в-docker)).

> [!NOTE]
> Ключ DeepSeek уходит напрямую на `api.deepseek.com`. Запросы к Gemini идут через прокси на Cloudflare Workers, и ключ передаётся в адресе запроса; адрес прокси — `GEMINI_URL` в `app/tools/llm.py`. Если не хотите отправлять ключ через этот прокси, подключите только DeepSeek или замените `GEMINI_URL` на адрес самого Google: `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent?key={key}`.

### Шаг 6. Запустите сервер

```sh
python app/tools/serve.py
```

В терминале появится строка `ITinder: http://127.0.0.1:8770/app/web/`. Сервер работает, пока открыт терминал; остановить его можно клавишами `Ctrl+C`.

Порт по умолчанию — `8770`. Другой порт передайте аргументом: `python app/tools/serve.py 8000`.

### Шаг 7. Откройте ITinder

1. Откройте в браузере **http://127.0.0.1:8770/** и включите звук.
2. На стартовой странице нажмите «Старт» (или Enter). Станция загружается, пока открыта стартовая страница; пролёт камеры по станции и звук начинаются с нажатия.
3. На станции метро зарегистрируйтесь (почта и пароль) или войдите.
4. Выберите роль: загрузите резюме в PDF, и шляпа сама определит специализацию и грейд. Можно выбрать специализацию и грейд вручную или роль рекрутёра.
5. После выбора камера сядет в поезд, и откроется 3D-комната.
6. Нажмите на монитор: на нём откроется рабочий стол. Набор значков на нём зависит от роли: соискателю — тесты на грейд, достижения ФСП, вакансии, приглашения, PDF-профиль; рекрутёру — проекты и найм, поиск соискателей.

**Готовые учётные записи.** В базе есть 500 сгенерированных соискателей с паролем `Seed-Applicant-2026`, например `glebrodionov@yandex.ru`. Чтобы посмотреть сторону рекрутёра, зарегистрируйтесь и выберите роль рекрутёра.

> [!IMPORTANT]
> Проходите весь путь в **одной вкладке**, начиная с `http://127.0.0.1:8770/`. Кто вошёл, хранится в `sessionStorage` вкладки. Если открыть `/resume3/` или `/os/` в новой вкладке, рабочий стол не узнает пользователя и напишет «Не удалось узнать, кто вы».

## Где хранятся данные

Регистрации, выбранные специализации, результаты тестов, проекты, приглашения и остальные записи — это JSON-файлы, по файлу на запись (устройство описано в `app/db/README.md`).

По умолчанию сервер пишет их прямо в `app/db`, а эта папка хранится в Git: новые записи появятся в `git status`. Чтобы рабочая копия оставалась чистой, укажите отдельную папку в переменной `APP_DATA_DIR`. Например, папка `data` исключена из Git:

Windows (PowerShell):

```powershell
$env:APP_DATA_DIR = "data"
python app/tools/serve.py
```

macOS / Linux:

```sh
APP_DATA_DIR=data python app/tools/serve.py
```

При первом запуске сервер скопирует в эту папку снимок записей из `app/db`, затем будет работать только с ней. Справочники (схема экранов, задания, реплики шляпы) по-прежнему читаются из `app/db`.

## После правок в коде

| Что изменили | Что сделать |
| --- | --- |
| `app/web` (станция) | обновить страницу в браузере: сервер запрещает кэш, сборка не нужна |
| `app/tools` (сервер, API) | перезапустить `python app/tools/serve.py` |
| `portfolio-inner-site/src` (рабочий стол) | `npm run build` в `portfolio-inner-site`, затем обновить страницу |
| `resume3/src` (комната) | `npm run build` в `resume3`, затем обновить страницу |

У внутренних приложений есть и свои серверы разработки: `npm start` в `portfolio-inner-site` (`http://localhost:3000/os/`) и `npm run dev` в `resume3`; с параметром `?dev` комната берёт рабочий стол с `localhost:3000`. Но они работают на других адресах, без API и без общей со станцией сессии, поэтому подходят только для вёрстки. Чтобы проверить ITinder целиком, собирайте приложения и запускайте `serve.py`.

## Если что-то не работает

| Что видно | Что сделать |
| --- | --- |
| `Порт 8770 занят — сервер уже запущен?` | остановите прежний сервер или запустите на другом порту: `python app/tools/serve.py 8771` |
| `/resume3/` отвечает 404 | не собрана комната — [шаг 4](#шаг-4-соберите-3d-комнату-resume3) |
| Монитор в комнате пустой или `/os/` отвечает 404 | не собран рабочий стол — [шаг 3](#шаг-3-соберите-рабочий-стол-portfolio-inner-site) |
| На мониторе написано «Не удалось узнать, кто вы» | вы открыли комнату или `/os/` в новой вкладке: начните с `http://127.0.0.1:8770/` и пройдите путь в одной вкладке |
| В окне написано «Сервер устарел: перезапустите app/tools/serve.py» | сервер запущен со старым кодом — перезапустите его |
| Нет звука | на станции звук включается кнопкой «Старт», в комнате — первым щелчком; проверьте, не выключен ли звук у вкладки и кнопкой динамика в комнате |
| Чёрный экран вместо станции или комнаты | в браузере выключен WebGL: включите аппаратное ускорение и перезапустите браузер |
| Шляпа не распознаёт резюме | проверьте ключи командой из [шага 5](#шаг-5-необязательно-подключите-свои-ключи-нейросетей). Gemini работает через прокси на Cloudflare; если провайдер его режет, включите VPN или положитесь на DeepSeek. Подробности по каждой нейросети сервер пишет в терминал и в консоль браузера |
| «Для PDF нужен шрифт Consolas или DejaVu Sans Mono» | нужен моноширинный шрифт: в Windows Consolas уже есть, в Linux установите DejaVu (`sudo apt install fonts-dejavu-core`). В macOS выгрузка PDF не поддерживается — запустите ITinder в Docker |
| Сборка `resume3` падает с `JavaScript heap out of memory` | дайте Node.js больше памяти: `NODE_OPTIONS=--max-old-space-size=4096 npm run build` (в PowerShell — `$env:NODE_OPTIONS = "--max-old-space-size=4096"`, затем `npm run build`) |

## Запуск в Docker

Если не хочется ставить Python и Node.js, ITinder можно запустить в Docker. Корневой `Dockerfile` сам собирает комнату и рабочий стол и запускает тот же сервер на порту `8080`:

```sh
docker build -t itinder .
docker run --rm -p 8080:8080 -v itinder-data:/data --env-file .env.local itinder
```

Откройте **http://127.0.0.1:8080/**. Записи хранятся в томе `itinder-data` и переживают перезапуск контейнера. Без ключей нейросетей уберите `--env-file .env.local`.

## Развёртывание в Northflank

Создайте Combined service из `Evsikoff/itinder`: ветка `main`, Dockerfile `/Dockerfile`, build context `/`. Порт `8080` публикуется как HTTP, HTTPS даёт Northflank. Для сборки `resume3` нужно не менее 4 ГБ RAM; приложение работает в одном экземпляре. Подключите постоянный диск к `/data`, чтобы регистрации и остальные записи сохранялись при перезапусках и новых развёртываниях.

Переменные окружения: `HOST=0.0.0.0`, `PORT=8080`, `APP_DATA_DIR=/data`. Ключи `GEMINI_API_KEY` и `DEEPSEEK_API_KEY` хранятся в Northflank Runtime variables/Secrets. Если прокси меняет заголовок `Host`, задайте `PUBLIC_ORIGIN` — публичный HTTPS-адрес без завершающего слеша. Проверка готовности: `GET /healthz`.

Снимок базы `app/db/` хранится в Git и входит в Docker-образ. При запуске сервер переносит новые записи из снимка в `/data` и не трогает уже существующие серверные записи. Журнал `.seed-imports.json` на постоянном диске отмечает обработанные файлы: повторные запуски не восстанавливают удалённые записи и не отменяют серверные изменения, а новые файлы из следующих снимков импортируются при развёртывании. Записи, созданные в опубликованном приложении, остаются на постоянном диске и обратно в Git автоматически не отправляются.

Секреты, `node_modules` и результаты сборки исключены из Git и из Docker build context.
