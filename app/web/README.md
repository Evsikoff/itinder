# Интерфейс ITinder

3D-сцена на three.js: бесконечная станция метро, пролёт камеры и страницы из `app/db/ui_scheme.json`. Сборка не нужна, библиотеки лежат в `vendor/`.

Запуск из корня проекта:

```
python -m pip install -r app/tools/requirements.txt
python app/tools/serve.py
```

Открытая станция сначала показывает стартовую страницу (`#start` в `index.html`, `src/startScreen.js`): логотип ITinder (`app/assets/itinder-logo.png`, копия `assets/branding/itinder-logo.png`), логотип команды (`app/assets/team.png`), подпись о проекте команды «Git-R-Done» для конкурса IT-решений и кнопка «Старт» с фокусом (Enter тоже запускает). Сцена грузится за ней; пролёт камеры и гул станции начинаются только по «Старт», а если сцена ещё не готова — после нажатия виден экран загрузки. Нажатие — и первый жест, после которого браузер включает звук. Возврат из комнаты кнопкой «Назад» загружает станцию заново, со стартовой страницей.

Приложение рабочего стола №6 «PDF-профиль» открывает соискателю тот же интерфейс профиля, который доступен рекрутёру, и позволяет скачать его в PDF. В собственном профиле всегда видна своя почта и задания по всем своим приглашениям. Над профилем — тумблер «Скрыть профиль от рекрутёров»: включённый кладёт `app/db/user_blocks/<id>.json` (`{"user_id", "created_at"}`), и окно рекрутёра №9 «Соискатели» перестаёт показывать соискателя в графе команды, в поиске по вакансии и по специализации и грейду; выключенный удаляет файл. Профиль остаётся доступен только рекрутёрам, с которыми уже есть приглашение или отклик, а сам соискатель по-прежнему видит вакансии и откликается. API: `GET /api/applicant/visibility?user_id=<id>` и `POST /api/applicant/visibility {"user_id", "hidden"}`. Приложение №4 «Приглашения» отдельно открывает существующий экран приглашений и откликов соискателя с уведомлениями и действиями над приглашениями.

«Скачать PDF» выгружает весь профиль: специализации и грейды, компетенции ФСП с подтверждающими соревнованиями, историю тестов, задания и сохранённые решения, принятые достижения ФСП. Документ оформлен как окно `cmd.exe`, поддерживает кириллицу, выделение текста и автоматическое разбиение на страницы. Для экспорта нужен ReportLab из `app/tools/requirements.txt` и системный шрифт Consolas (Windows) либо DejaVu Sans Mono (Linux). API чтения: `/api/applicant/profile?user_id=<id>` и `/api/applicant/profile/pdf?user_id=<id>`; просмотр и экспорт ничего не записывают в БД — пишет только тумблер видимости.

Открыть http://127.0.0.1:8770/. Сервер отдаёт только папку `app/` (кроме записей пользователей `app/db/users` и `app/db/user_specializations` и кода `app/tools`), поэтому пути картинок из схемы (`\app\assets\...`) работают как есть, и комнату `/resume3/` — собранное внутреннее приложение из `resume3/public` (после правок в `resume3/src` его нужно пересобрать: `npm run build` в `resume3`), и `/os/` — «операционную систему» на мониторе в этой комнате, сборку `portfolio-inner-site/build` (её resume3 открывает в iframe; после правок в `portfolio-inner-site/src` — `npm run build` в `portfolio-inner-site`, базовый путь `/os/` задан полем `homepage` в его `package.json`). Регистрация, вход, распознавание резюме и запись специализации работают только с этим сервером: он же принимает `POST /api/users`, `/api/login`, `/api/resume` и `/api/user_specializations`.

На хостинге сервер запускается с `HOST=0.0.0.0` и `PORT=8080` (или портом платформы).
`GET /healthz` и `HEAD /healthz` возвращают 200 для проверки готовности.
HTTPS-прокси должен сохранять публичный заголовок `Host`; если он меняет его,
задайте `PUBLIC_ORIGIN=https://<домен>` для проверки источника POST-запросов.
`APP_DATA_DIR=/data` переносит изменяемые записи в постоянный том: `users`,
`user_specializations`, `user_names`, `user_tests`, `user_fsp`, `companies`,
`user_project_company`, `projects_jobopenings`, `invitations`, `user_blocks`.
Справочники читаются из `app/db` в образе, поэтому обновляются вместе с приложением.
Без `APP_DATA_DIR` локальная работа по-прежнему использует `app/db`.
Нейросетям нужны секреты `GEMINI_API_KEY` и `DEEPSEEK_API_KEY`; локально они могут
лежать в игнорируемом файле `.env.local`. Для PDF в Linux установите DejaVu Sans Mono.

## Устройство

| Файл | Что делает |
|---|---|
| `src/config.js` | Размеры станции, светильники, путь камеры, параметры цепи и таблички |
| `src/station/` | Процедурная станция: текстуры, бесконечный ряд светильников в шейдере, поезда; у дверей, в которые садятся, борт вырезается, створки разъезжаются, за ними — салон |
| `src/camera.js` | Камера: пролёт при старте, стоянка с кадром по габаритам страницы (на уровне глаз или вплотную к странице — `camera.mode` в строке `Page`) и лёгким параллаксом, приближение колёсиком, переезд к другой странице |
| `src/audio.js` | Звуки из `app/assets/sfx`: гул станции, шаги при переезде к другой странице, звуки объектов по нажатию и по клавишам |
| `src/navigation.js` | Переход по `link_to_page`: страница уезжает за потолок, камера едет вперёд, новая спускается из люка |
| `src/boarding.js` | Посадка в поезд после выбора специализации и грейда: камера идёт к дверям вагона напротив страницы, двери открываются, камера входит, экран гаснет и открывается комната `/resume3/` |
| `src/actions.js` | Действия по `additional action`: `Creating a user record` — регистрация через `POST /api/users`, `Authorization` — вход через `POST /api/login`, потом комната (специализация уже записана) или страница, куда ведёт регистрация (выбор роли), `User resume recognition` — выбор PDF и экран шляпы, `Save selection and enter the room` — запись своего выбора через `POST /api/user_specializations`. После записи специализации (своей или от шляпы) — посадка в поезд |
| `src/api.js` | Запросы к API сервера. Пользователю — короткий текст ошибки, в консоль браузера — подробности: что случилось с каждой нейросетью (`failures`), исключение на сервере (`detail`), сервер не запущен |
| `src/session.js` | Текущий пользователь вкладки: кто зарегистрировался (в `sessionStorage`) |
| `src/filePicker.js` | Системный диалог выбора файла |
| `src/hat/hat.js`, `hat.css` | Экран распределительной шляпы: вступление с субтитрами, пока резюме распознаётся (`POST /api/resume`), реплика на итог встык, вердикт картинками и выбор — согласиться (`POST /api/user_specializations`), другое резюме, ручной выбор |
| `src/hat/replicas.js` | Реплики шляпы из `app/db/hat_replicas.json`: вступление и реплика на итог |
| `src/hat/subtitles.js` | Субтитры из текста реплики: фразы по времени пропорционально длине |
| `src/startScreen.js` | Стартовая страница: ждёт нажатия «Старт», до него сцена не начинает пролёт и гул станции не звучит |
| `src/notice.js` | Сообщение внизу экрана об итоге действия |
| `src/page/scheme.js` | Чтение схемы, выбор элементов страницы и её корня |
| `src/page/layouts.js` | Компоновки содержимого (`Layout`) |
| `src/page/pageLayout.js` | Корректировки сборки страницы из строки `Page` (`Layout` — JSON, формат в `app/db/README.md`) |
| `src/page/metroSign.js` | Объект «табличка как в метро» |
| `src/page/chalkboard.js` | Объект «школьная доска»: поле ввода, набранное пишется мелом |
| `src/page/birdcage.js` | Объект «продолговатая клетка»: поле пароля, каждый символ — шарик на физике |
| `src/page/textField.js` | Невидимый `<input>` за 3D-полем ввода: раскладки, вставка, стрелки, Tab, экранная клавиатура |
| `src/page/hardware.js` | Подвесная фурнитура: тросы, ушки, кольцо |
| `src/page/fonts.js` | Загрузка шрифтов |
| `src/page/chain.js` | Цепь на физике Rapier (одна или две на объект); невидимый трос не даёт ей растянуться под грузом |
| `src/page/page.js` | Сборка страницы: корень висит на цепи в люке страницы, дочерние элементы — строками под своим `anchor_point_id`, с поправками из строки `Page`; подъём и спуск страницы |

Новый `object_type` добавляется в `OBJECT_TYPES` в `page.js`, его звуки — в `OBJECT_SOUNDS` в `audio.js`, новый `Layout` — в `LAYOUTS` в `layouts.js`, новое `additional action` — в `ACTIONS` в `actions.js`.

Каждая страница висит в своём месте станции: страница N — на `PAGES.spacing · (N − 1)` метров дальше страницы 1, над ней в потолке люк. Люк расширяется под страницу шире него. Камера встаёт так, чтобы страница поместилась и по высоте, и по ширине, и встаёт заново при смене размера окна.

Колёсико мыши приближает камеру к объекту под указателем: она подлетает к этой точке, пока та не встанет посередине кадра прямо перед ней, но не ближе `ZOOM.closest` (0,3 м) к габаритам любого объекта страницы — если объект качнётся навстречу, камера отступит. Пока указатель стоит на месте, следующие щелчки ведут к той же точке; мимо объектов — к ближайшему месту страницы. Колёсико назад отводит камеру обратно к стоянке, дальше неё камера не отходит. Переход на другую страницу и посадка в поезд начинаются с того места, где камера сейчас, и сбрасывают приближение. Ctrl с колёсиком — масштаб браузера.

Клик по элементу со ссылкой открывает страницу, по полю ввода (доска, клетка) — даёт ему фокус, по остальным — толкает табличку. Элемент с `additional action` при нажатии качается и выполняет действие (по `click`: только из него телефон откроет диалог выбора файла), итог (или ошибка: пустая почта, почта уже занята) появляется внизу экрана, а при неверных почте или пароле на входе — с кнопкой «Зарегистрироваться», которая ведёт на страницу регистрации; ссылка такого элемента открывается только после успешного действия, а отменённое действие (диалог закрыт, возврат к ручному выбору) ничего не пишет и никуда не ведёт. Записанная специализация (кнопка грейда или согласие с шляпой) и вход пользователя, у которого она уже есть, вместо ссылки ведут в поезд и дальше в комнату; пока идёт посадка, клики по сцене не принимаются. Назад из комнаты — станция загружается заново. Клик мимо полей снимает фокус, Esc тоже; Tab переходит к следующему полю. Значение поля: `itinder.pages.page.nodes[i].object.field.value`. Распознавание резюме пишет в консоль браузера, какая нейросеть ответила и что решила, а если не справилась одна или обе — почему (прокси или VPN не запущен, таймаут, ключ, квота, ответ не JSON). Из консоли браузера: `itinder.pages.go(2)` открывает страницу 2, `itinder.debug.advance(5)` прокручивает сцену на 5 секунд.

## Звуки

Гул пустой станции (`rumble.mp3`, громкость 30 %) звучит по кругу всё время. Он начинается с нажатия «Старт» на стартовой странице: это нажатие — и первый жест, после которого браузер включает звук. Пока камера едет от страницы к странице или к дверям поезда и в вагон, по кругу звучат шаги (`footsteps.mp3`); пролёт при старте идёт без них. Двери открываются без звука. Пока гаснет экран перед комнатой, затихает и станция. Нажатие на табличку — шлепок (`slap1–3.mp3`; записаны на 35–40 дБ тише остальных, поэтому после загрузки каждый усиливается до пика на полной шкале — `normalize` в `SOUNDS`), клавиша, пока в фокусе доска, — мел (`writing.mp3`, новое нажатие обрывает прежний звук), клетка — шарик (`ball1–4.mp3`). Из нескольких вариантов звучит тот, что за сессию (с загрузки страницы) звучал реже всех, из равных — случайный. В скрытой вкладке звук на паузе, как и сцена. Пока открыт экран шляпы, станция звучит тише (20 %), а сцена за ним не рисуется. Счётчики: `itinder.sounds.plays`.
